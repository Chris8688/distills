# 股息率模式·四进三出（A股）

一个**投资思路蒸馏**，不下真单。
规则出处、证据等级、校准 → `docs/01-蒸馏笔记.md`；纸面账户与同步口径 → `docs/02-纸面交易与同步.md`。

所有命令在本目录下运行。纸面账户账本、Notion 同步进度和日志放在仓库外的 `DISTILL_STATE`
（缺省 `~/.local/share/distills/dividend-4in3out/`），行情与财报缓存在 `DISTILL_CACHE`（缺省 `~/.cache/distill/dividend-4in3out/`）。

## 定时任务（可选）

`daily.sh` 自动跑：作者净值 → `paper.py run`（同一交易日只交易一次，周末/节假日自动跳过）→ 持仓体检 + 买入清单。
输出 `$DISTILL_STATE/logs/<日期>.log` 与 `logs/last_run.json`；失败弹 macOS 通知。用 cron 或 launchd 每天北京时间 17:00 后调用。
**不做**雪球持仓/调仓（要登录）和 Notion —— 由下面默认流程第 0 步补齐。

## 默认流程（用户只说「股息率模式」/ 直接调用、没有具体问题时，都做，**选股结果必须展示给用户**）

0. **看定时任务**：读 `$DISTILL_STATE/logs/last_run.json` —— `status` 不是 ok 就先报告失败步骤和日志；
   `notion_pending` 有积压就在第 4 步一次补齐。最近几天的成交从日志汇总给用户。
1. **同步雪球**（见 ②）—— 报告作者有没有新调仓。
2. **纸面账户**：`python3 paper.py run`（同一交易日已跑过会只打印，不重复交易）—— 报告本次成交、卖出原因、复核项、分红再投入。
3. **选股**（核心产出，不能省）：
   - `python3 screen.py --rules observed --top 30` → 给用户看**买入清单前 30**（股息率、预期股息率、扣非、保底分红率、周期股标记）。
   - `python3 screen.py --rules observed --paper` → **纸面账户持仓体检**：哪些该卖 / 复核 / 持有不加、换仓建议、可选升级换股。
   - 对照作者：清单头部和作者持仓的重合（`--cube` 或 `paper.py status` 的「作者也持有」列）。
4. **Notion 记账**（见 ④）—— 有新流水 / 净值才写。

最后用一张短表总结：本次买卖、清单前 10、需要人看的复核项。用户问的是具体问题（某只能不能买、只看清单等）就只做对应的那一步。

## ① 筛选器

```bash
python3 screen.py                         # 全市场买入清单（前 40）
python3 screen.py --hold 600066,601318    # 持仓体检 + 换仓建议
python3 screen.py --codes 600900          # 只看几只的明细与判定理由
python3 screen.py --cube --rules observed # 用作者最新持仓快照做校验
```

| 规则档 | 卖出条件（股息率 ≤3% 三档都卖） | 买入额外条件 |
|---|---|---|
| `1.0`（缺省） | 最新累计扣非同比 < -10% | 扣非 ≥ -10% |
| `observed`（纸面账户用） | 扣非 < -30%；或 扣非 < -10% **且** 扣非口径预期股息率 < 4%；其余扣非 < -10% 只标「复核」继续持有 | 扣非 ≥ -10%（复核状态只许持有、不许新买） |
| `strict` | 同 1.0 | 扣非 > 0、现金流/净利 > 0.6（金融业豁免） |

observed 的卖出规则是用作者 2023 起 27 次「扣非 < -10%」决策拟合的：命中其卖出 12/18，误卖其留着的 1/9（docs/01 §2.3）。

三档共用的买入门槛：股息率 ≥4%、连续分红 ≥4 年、保底分红率 ≤100%、分红怪异（>10× 前 4 年中位）不买、**分红率 >100% 连续 ≥2 年不买**（作者原文；单年只标注）、
**不接飞刀（相对版：过去一年前复权涨跌比全部长期分红股中位数多跌 25% 以上不买）、不买利润暴增（TTM 归母净利同比 >+70% 不买）**
（2026-10-05 起，docs/04 §7：17 起点年化 +0.88pp、买错率 26.4% → 22.3%、大赢家不减；相对版不误挡全市场暴跌后的反弹）。
这些都只挡**买入**：持仓不因它们卖出，体检里显示为「持有不加」。
**买入清单按「可持续股息率」= min(股息率, TTM 盈利收益率) 排序**，不是按静态股息率 —— 后者会把一次性超额分红排到最前（2026-10-02 修正）。
其余参数：`--slots`（等权只数，`--paper` 时取账户的 15）、`--min-mcap`（亿）、`--offline`、`--json`。首次全量约 8~10 分钟，之后走缓存。

## ② 同步雪球作者的持仓与调仓

调仓接口要登录、页面有阿里云滑块验证 —— **滑块和登录都由用户自己完成，Claude 不点滑块、不输密码。**

1. `python3 sync_xueqiu.py nav`（匿名即可，拉净值到 `data/xueqiu/nav.csv`）。
2. 浏览器：`tabs_context_mcp` → 新标签页打开 `https://xueqiu.com/P/ZH1027925`，等 5 秒后用 JS 检查
   `!!(window.SNB && SNB.cubeInfo)` 与 `SNB.currentUser`。
   - 标题是「滑动验证页面」或 `SNB.currentUser` 为空 → **停下来请用户在这个标签页里完成滑块并登录雪球**，用户说好了再继续。
3. 在组合页执行 `python3 sync_xueqiu.py js` 打印的脚本（缺省 1 页 = 最近 50 次调仓；补历史用 `--pages 10`）。
   返回 `ERR|...` → 没登录或被验证拦了，回到第 2 步。返回首项 `MORE|n` → 分批读 `window.__xq.slice(99, 198)` …
4. 把返回的行原样喂给 `python3 sync_xueqiu.py ingest <<'EOF' … EOF`：调仓按 (日期, 代码, 目标权重, 价格) 去重追加到
   `data/xueqiu/rebalancing.csv`，持仓成分有变化（或距上次 ≥7 天）就写 `data/xueqiu/holdings/<日期>.csv`，摘要追加到 `sync_log.md`。
5. 关掉自己开的标签页。`python3 sync_xueqiu.py status` 看结果。

## ③ 纸面账户（1000 万人民币，observed 档，15 只等权）

```bash
python3 paper.py run --dry-run   # 先预演
python3 paper.py run             # 落账：除权除息 → 卖出 → 不出则不进地补位 → 记净值
python3 paper.py status          # 持仓、盈亏、与作者持仓重合度
```

- 按「最近一个已收盘交易日」收盘价成交；同一交易日只交易一次（重跑只打印，`--force` 强制）。
- 停牌不交易、涨停不买、跌停不卖；一手取整；佣金 0.025%（最低 5 元）+ 过户费 0.001% + 卖出印花税 0.05%。
- 除息日入账现金分红（红利税按持有天数近似）、除权日加送转股；**税后分红再投入派息的那只**（一手取整，不足一手或该股被卖就留现金）。
- 15 只、单行业 ≤3 只、每日检查：依据见 docs/06（2026-10-06 由 30 只改为 15 只：17 起点年化 14.4% → 17.4%，回撤不变深；代价是单只踩雷影响翻倍、波动 15% → 18%）。
- 账本 `$DISTILL_STATE/paper/`（account.json / trades.csv / nav.csv）**不进 git，是唯一事实源**；建议先跑 ② 再跑 ③，净值表里才有当天的作者对照。

## ④ Notion 记账（可选，每次 `paper.py run` 落账后做）

先在 Notion 建一个页面，下设方法论页和三张表：`trades`（交易流水）/ `positions`（当前持仓）/ `nav`（每日净值），
把它们的 id 用 `paper.py notion-mark --db root=…,methodology=…,trades=collection://…,positions=collection://…,nav=collection://…` 记进 `paper/notion.json`。

1. `python3 paper.py notion-pending` → 未同步的 `trades`、`nav`，全部 `positions`（带 `notion_page`），以及 `closed_positions`。
2. 用 Notion MCP：
   - `trades` 每条 → 在交易流水建一行（标的=name、流水号=id、交易日=session、代码、方向、股数、价格、金额、费用、税、成交后现金、原因、状态=有效）。
   - `nav` 每条 → 在每日净值建一行（交易日、总资产、现金、市值、净值、累计收益%=return_pct、持仓只数、作者组合净值=cube_nav）。
   - `positions`：`notion_page` 为空 → 新建行；否则更新股数 / 成本价 / 现价 / 市值 / 权重% / 盈亏% / 作者也持有。
   - `closed_positions` → 把该页的「状态」改成「已清仓」。
3. `python3 paper.py notion-mark --trades <id,…> --nav <session,…> --pos <code=page_id,…> --drop <清仓代码,…>` 记进度；
   再跑一次 `notion-pending` 确认 trades/nav 为空。

## 边界（别越界）

- **单因子、轮动**：持有期中位数 162 天，不是买入持有；不要拿买入持有的评估标准替代它，也不要反过来。
- **周期股**：标了「强周期·看PBR」的高股息常是峰值利润分红，要另外做周期顶检查（见 docs/01 §4）。
  脚本**不剔除**它们，剔除就不是这个策略了。
- **新闻 / 情绪类工具给的多空标签不参与判断**。
- 纸面账户不是回测：运行时间短的纸面账户没有统计意义。历史回放见 docs/05。
- 不是投资建议；数据源（东财/新浪/TickFlow）偶有缺漏，**下单前核对公司公告的分红方案**。
